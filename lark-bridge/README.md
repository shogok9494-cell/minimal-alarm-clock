# lark-bridge

Claude から Lark のチャットへメッセージを送るための最小ブリッジ。

## なぜこれが必要か

Claude には **Lark 用の公式コネクタが存在しない**（コネクタディレクトリに Slack はあるが Lark／Feishu は無い）。
また Claude Code の実行環境はセッションごとに作り直される使い捨てコンテナなので、
その場でインストールしたものは次回に一切引き継がれない。

そのため「設定でONにすれば繋がる」という方法は無く、送信手段を**リポジトリとして外に持っておく**必要がある。
これがそのリポジトリ。

## いまできること / できないこと

| 方向 | 状態 | 仕組み |
|---|---|---|
| Claude → Lark | ✅ これで可能 | グループのカスタムボット Webhook に POST |
| Lark → Claude | ❌ 未対応 | 常時稼働するサーバとカスタムアプリ（app_id/app_secret）が別途必要 |

このリポジトリは**一方向（Claude → Lark）専用**。
Lark 側から話しかけて Claude に届かせるには、別途 Webhook 受け口のホスティングが必要（第2段階）。

## セットアップ（Lark 側・所要3分）

管理者権限は不要。通知を受けたいグループで作業する。

1. Lark で対象のグループを開く
2. 右上の「**…**」→「**設定**」→「**ボット**」
3. 「**ボットを追加**」→「**カスタムボット（Custom Bot）**」を選ぶ
4. 名前（例: `Claude`）と説明を入力
5. **セキュリティ設定**で「**署名検証**」にチェックを入れ、表示された **シークレット** を控える
   - 「IP許可リスト」は使わない（実行環境のIPが毎回変わるため）
   - 「キーワード」でも代用できるが、署名検証のほうが安全
6. 「**追加**」を押すと **Webhook URL** が表示されるのでコピー

> ⚠️ Webhook URL とシークレットは**パスワードと同等**。
> これを知っている人は誰でもこのグループに投稿できる。git にコミットしないこと。

## セットアップ（実行側）

```bash
cp .env.example .env
# .env を開いて、控えた URL とシークレットを貼る
```

## 使い方

```bash
# .env を読み込んで送信
set -a && . ./.env && set +a
npm run send -- "ブリッジ確認OK（$(TZ=Asia/Tokyo date '+%Y-%m-%d %H:%M')）"
```

成功すれば `送信成功` と出て、Lark のグループにメッセージが届く。

## 設計上の約束

- **秘密情報をログに出さない** — 失敗時も URL やシークレットは表示せず、エラーの要点だけ出す
- **依存パッケージゼロ** — Node 18+ の標準機能（`crypto` / `fetch`）だけで動くので `npm install` 不要
- **送信前に検証** — URL 未設定や空メッセージはネットワークに出る前に落とす

## テスト

```bash
npm test
```

署名生成は Lark 公式ドキュメント記載のアルゴリズムと一致することを確認済み:

```
string_to_sign = `${timestamp}\n${secret}`
sign = base64( HMAC-SHA256(key = string_to_sign, message = "") )
```

※ HMAC の鍵とメッセージが直感と逆（鍵が `string_to_sign`、メッセージが空文字）。ここを間違えると `sign match fail` になる。

## よくあるエラー

| 症状 | 原因 |
|---|---|
| `code=19021 sign match fail` | シークレットが違う／署名検証をONにしたのに `LARK_WEBHOOK_SECRET` 未設定／コンテナの時計がずれている |
| `code=9499` | Webhook URL が誤り、またはボットがグループから削除された |
| `送信するテキストが空です` | 引数を渡していない |
| キーワード設定時に届かない | 本文に設定したキーワードが含まれていない |

## 次の段階（Lark → Claude）

双方向にするには以下が追加で必要:

1. Lark 開発者コンソールで**カスタムアプリ**を作成し `app_id` / `app_secret` を発行
2. 権限スコープ `im:message` / `im:message:send_as_bot` を付与
3. 常時稼働する Webhook 受け口をホスティング（Vercel 等）し、イベント購読 URL として登録
4. その受け口から Claude を呼び出し、応答を Lark API で返す

1〜2 は Lark の管理者権限が必要。
